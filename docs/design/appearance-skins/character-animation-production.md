# 晴海蓝人物动画制作与交付建议

日期：2026-10-21。状态：已完成[人物动作最小试片](character-motion-trial-v1/README.md)、[动作增强对照 v2](character-motion-trial-v2/README.md)及[冷启动到动态主页完整预演 v3](motion-preview-v3/README.md)：新增半闭眼、闭眼素材，以局部眼睛合成和参数网格实现眨眼、发丝与服装起伏，并串联界面入场和主页循环。尚未制作正式 Cubism 分层、模型工程或包含转头、挥手的完整人物演出。

## 1 建议路线

制作端采用 Live2D 的分层、补画、网格/变形绑定和动画流程，交付端先导出冷启动与主页循环两段透明视频，由 Hemi 组合真实界面、题字和场景播放。同一模型的两段动作共享静止姿态，便于衔接。

这一选择是基于当前需求的工程建议：两段都是预先设计的演出，首版用本地视频即可表达，先验证完整人物成片和透明解码。运行时模型是另一种可交付出口，待确有逐参数驱动需求时再评估 Cubism SDK for Web 与 Core 的接入；当前没有安装 SDK 或改变应用安全策略。

官方流程参考：[素材分离](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)、[拆图与补画教程](https://docs.live2d.com/4.2/en/cubism-editor-tutorials/psd/)。视频导出能力参考[图片与视频导出](https://docs.live2d.com/en/cubism-editor-manual/exporting-images/)；Web 运行时参考[官方 Framework](https://github.com/Live2D/CubismWebFramework)与[模型加载说明](https://docs.live2d.com/en/cubism-sdk-manual/model-web/)。

## 2 针对当前人物的拆层与补画

现图是单张扁平 PNG，透明背景不代表人物内部已有可动图层。拆图时保留统一画布和相同原点，补全被其他部件遮住的区域，避免部件移动后露出空洞。

| 部分 | 建议层与补画 |
| --- | --- |
| 眼睛与眉毛 | 左右分开；眼白、虹膜、瞳孔/高光、上睫毛/眼睑、下眼睑、眉毛；补正常睁眼与闭眼状态。原图闭着的那只眼需要补齐睁开后的内容 |
| 头部与脖颈 | 脸底、轮廓、耳朵与脖颈；补头发下面的脸及转头/点头时可能露出的脖颈 |
| 头发 | 刘海、呆毛、左右侧发与后发分别拆层，按实际摆动需要分束；补发束重叠后的缺失区域 |
| 服装与饰物 | 上身服装、袖子、发饰、蝴蝶结与宝石；按呼吸、衣饰滞后摆动的需要拆分 |
| 手臂与手 | 如果要挥手，准备上臂、前臂、手掌及袖口，并补完整手势。当前构图不能直接提供所有抬臂后可见的内容 |

现有 PNG 可以作为底图。辅助生成可用于局部补画参考，但每层仍须对齐、修边并核对人物一致性；生成一张近似人物图不等于可绑定的分层模型。首次先做晴海蓝，确认拆层与成片质量后再扩展其余四款。

## 3 动作制作

将图层导入模型编辑器，建立网格、变形器及眼睑开合、头部角度、躯干起伏、发束和饰物摆动等参数，再制作动作。小幅点头/转头以模型变形表达；动作超出已有视角或手势范围时补充对应原画。

| 动作 | 首支建议 | 结束要求 |
| --- | --- | --- |
| 冷启动 | 约 6s；看向用户、轻眨眼、一次抬手引导，配合界面展开 | 回到主页循环的起始/静止姿态 |
| 主页循环 | 约 10–15s；呼吸、轻微发丝/饰物滞后和低频眨眼，动作幅度小 | 位置、表情、透明边缘与速度均可平顺循环 |

题字、光带与 Hemi 窗口不烘焙进人物动画，分别由应用合成，保留当前窗口缩放和真实页面交接的控制能力。主页不循环挥手或整段启动演出。

## 4 交付物与 Hemi 接入

交付可编辑的分层 PSD、模型与动画工程，以及：

- startup.webm：透明人物冷启动前景，无声。
- idle.webm：透明主页循环，无声；输出与 startup 相同的画布、锚点和人物比例。
- rest.png：静态休止姿态，与启动结束及循环起始画面匹配。
- poster.png：冷启动播放器准备/失败时使用的首帧。
- cue.json：时长、UI 出现/交接时间点、人物安全区域和归一化锚点；字段待接入时固化。

Cubism 支持透明 WebM 导出；这只是制作出口能力。Hemi 的 Electron 44 仍须实测目标平台的透明边缘、解码、缩放、首帧和资源释放。正式编码与分辨率由试片结果决定，不承诺所有透明视频编码均能直接使用。

应用以独立人物层播放本地资源。冷启动与真实页面并行准备，结束衔接同皮肤主页循环；输入、阅读、失焦、隐藏和减少动态效果时保留静态人物并停止常驻调度。切换皮肤时取消旧播放代次并释放旧资源，不增加独立背景开关。

验收须连续播放检查眨眼是否自然、发丝是否穿帮、手势是否变形、透明边缘是否有色边，以及循环与静态回退是否跳姿态。目前已串联冷启动和主页的完整视觉预演，并保留人物局部动作试片；它没有转头、挥手或口型，眼睛关键帧混合也不能替代正式眼睑绑定。真实应用启动接入、正式模型交付和完整人物动作仍待制作。
