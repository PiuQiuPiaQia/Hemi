# Bot 与普通对话的复用约定

日期：2026-10-22。依据：[需求 1.2](../../requirements/cloud-bot.md) R-05、R-16。

普通对话是 Bot 的页面和通用功能基线。正式实现共用会话列表、消息流、输入区和过程组件，通过运行环境提供数据与能力。Bot 保留独立 Tab、首次连接引导和云端常驻特性。以后新增通用对话能力也在共享层实现，两种环境一起验收。

## 保持一致的部分

| 区域 | 沿用普通对话 |
| --- | --- |
| 会话列表 | 新建、切换、历史查看、重命名、删除、复制 ID、时间分组和排序、窄窗抽屉 |
| 消息流 | Markdown 和代码、复制、用户消息编辑重发、失败重试、执行过程、任务卡、授权与交付物 |
| 输入区 | 文字编辑、发送与换行、输入历史、草稿、附件、拖入文件、粘贴图片、待发送队列与停止操作 |
| 工具栏 | `/`、`@`、模型、思考强度、访问范围和用量等现有交互及位置 |

只复用当前产品已经存在的交互，不以本稿新增一套会话操作规则。语音相关功能不进入 Bot。

## Bot 环境的差异

| 项目 | 处理 |
| --- | --- |
| 运行主机 | 当前绑定的 Linux 云服务器；任务、文件、授权、模型请求和状态属于该主机 |
| 页面顶部 | 小型同步模型入口、服务器连接状态和 Bot 设置 |
| 模型 | 来源是手动同步并经云端确认的 Bot 可用模型目录 |
| 目录 | 默认空间起步；复用目录选择位置，内容为服务器真实文件夹列表 |
| 附件 | 保留普通输入体验；先将用户选中的文件传到云端，取得就绪身份后使用 |
| 引用与能力 | 查询当前 Bot 的会话、文件、目录及可用技能等资源；不混入仅本机可用的对象 |
| 权限与用量 | 相同的展示组件；数据和控制动作绑定云端权限与实际调用记录 |
| 常驻与失联 | 切换或退出本机不停止已受理任务；失联保留草稿和最近记录，重连核对云端结果 |
| 语音及本机采集 | 去掉语音输入、实时通话、播报、录音、录屏和本机屏幕／窗口采集入口，能力层也不启动相应设备和会话 |

附件输入与本机采集分开处理：用户选文件或粘贴图片仍可使用，Bot 不因此获得读取整个本机文件系统或持续采集屏幕的能力。依赖云端尚未具备能力的候选须说明原因，不默默回退到本机。

## 组件与数据边界

现有 [VoiceScreen](../../../src/renderer/src/windows/voice/voice-screen.tsx)、[ConversationSidebar](../../../src/renderer/src/windows/voice/sidebar.tsx)、[TextComposer](../../../src/renderer/src/windows/voice/text-composer.tsx) 已覆盖主要交互。正式开发从这些组件提取共享的对话层，语音宿主按能力挂载。

共享组件通过适配层获取会话、消息、队列、附件、引用候选、技能、模型、权限和用量。普通对话适配本机服务，Bot 适配云端 Host；组件不直接假定 `window.hemiVoice` 的本机会话就是当前数据源。会话与运行身份应包含运行环境，避免同名目录或同一消息 ID 串到另一台主机。

编辑重发、重试、队列编辑和停止保持原有操作语义；云端负责受理、作废原回合及过滤迟到回写。正在运行的任务保留其模型和目录快照，后续指令的选择不能反向修改它。语音快捷键和后台服务也按当前环境门控，普通对话的语音功能保持正常。
