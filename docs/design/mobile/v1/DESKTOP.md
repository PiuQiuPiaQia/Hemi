# PC 端设备配对交互稿

2026-10-23。与手机扫码稿配套，覆盖已有可信 PC 为自己的手机签发邀请、核对、批准及撤销的完整操作路径。本稿不调用生产 IPC，不连接真实 Bot，不改变服务器授权。

## 预览与入口

[打开 PC 交互稿](http://127.0.0.1:5175/desktop.html?scene=settings)，[手机扫码稿](http://127.0.0.1:5175/?scene=pair-scan)。两端同用已有的本机 Vite 服务。

PC 正式入口位于左侧 Bot 页右上角“Bot 设置”，不是新增全局设置页。已核对实际 `src/renderer/src/windows/bot/settings.tsx` 与 `page.tsx` 的入口及弹窗结构。本稿引用真实桌面 token 和 Bot 弹窗 CSS，保留标题 16px、列表／正文 13px、对话正文 15px。窗口导航为演示外壳；此次新增的是弹窗中的设备区和顶部请求提示，不替代原有模型、连接、维护与服务操作。

## 操作要求

| 场景 | PC 行为 | 与手机的关系 |
| --- | --- | --- |
| Bot 设置 | 设备区新增“连接新设备”和“已连接设备”。显示连接状态、默认空间与模型信息。 | 手机流量和 Wi-Fi 均可；两端分别访问云端 Bot。 |
| 生成邀请 | 居中弹窗，二维码与说明分列；显示 Bot 目标、两分钟倒计时、一次性语义和取消。 | 邀请只允许申请；不能直接访问会话。 |
| 收到请求 | 顶部出现“新设备请求 1”，不跳走当前对话、不清理草稿。设置中也可进入待确认项。 | 不自动批准第一个扫码者。 |
| 核对 | 显示请求设备名、双方核对码、明确的权限范围；核对勾选后才启用“允许连接”，并提供拒绝。 | 名称由手机提供，必须以自己手机屏幕的核对码为准。 |
| 收起请求详情 | X／Escape 仅收起详情，待处理提示仍保留；拒绝必须明确点击。 | 不把收起弹窗当成授权或拒绝。 |
| 批准之后 | 先显示“已允许连接”，设备表为“等待首次连接”；收到手机真实完成结果后才更新最近连接。 | 批准和手机完成连接是不同事实，不先报成功。 |
| 设备管理 | 表格显示设备、最近连接和撤销操作，当前 PC 明确标识。 | 每台设备独立身份；邀请码失效不影响已配对设备重连。 |
| 撤销 | 先确认具体设备、其他设备与云端任务的影响，以及缓存不可收回。 | 以 Bot 的撤销回执为准。 |
| 结果待核对 | 取消或撤销回执未知时，显示“待核对”；不先移除设备或展示成功。 | 恢复连接后核对原邀请／操作，不自动重复授权。 |
| 过期／拒绝 | 移除旧二维码或允许按钮；重新生成清除旧核对勾选。 | 旧邀请不能用于第二台设备。 |
| 断线 | 禁止签发与批准；取消结果未知时隐藏旧码，恢复后核对。 | 不认为关闭本地弹窗就已在云端取消。 |
| 旧 Bot／权限不足 | 显示不可用原因，禁止签发与撤销。 | 先升级并配置安全配对入口，或使用有管理能力的可信设备。 |

所有批准操作须绑定邀请 ID、请求 ID、设备公钥与稳定操作 ID；界面勾选不是服务端权限判断。私钥不传到 PC，也不放入二维码。真实协议见 [Bot 自有设备配对方案](../bot-device-pairing.md)。

## 评审操作

页面顶部可切换 8 个场景。窗口外下方的“演示操作”可模拟手机申请、过期、手机完成首次连接、PC 断线，以及撤销回执丢失。这些控件不属于正式产品。

建议评审路径：

1. Bot 设置 → 连接新设备 → 模拟手机扫码申请 → 核对 → 允许 → 已连接设备 → 模拟手机完成连接。
2. 收到连接请求 → 打开 → 收起详情 → 从顶部再次打开，检查对话草稿仍保留。
3. 设备列表 → 模拟撤销回执丢失 → 撤销 → 核对结果；再体验生成二维码后断线并取消。
4. 检查旧 Bot、权限不足、过期与拒绝，不应通过隐藏入口绕过限制。

手机稿与 PC 稿共用配对 reducer、二维码示例、核对内容和确认规则，各自使用移动底部面板或桌面居中弹窗。两个预览标签页不直接联网同步；演示事件代替尚未实现的 Bot 推送。PC 草稿使用独立的 `hemi-desktop-design-v1` 命名空间，与手机演示数据隔离。

## 验证与范围

```sh
node node_modules/vite/bin/vite.js build --config docs/design/mobile/v1/vite.config.mjs
node docs/design/mobile/v1/verify-desktop.mjs
node docs/design/mobile/v1/verify.mjs
```

同一构建输出包含 `index.html` 与 `desktop.html`。桌面脚本启动／关闭自己的开发服务、构建预览和验证浏览器，人工预览服务继续保留。桌面验证报告与源码哈希位于 `.visual/workflow/desktop-pairing-design/report.json`；视觉记录见 `.visual/workflow/vision-report-desktop-pairing.md`。

验证环境为 macOS 26.5.1 arm64、Node 22.22.3、Chrome 155；基于当前 main 提交加本目录未提交源码，准确提交和哈希以报告为准。桌面开发／构建各 10 组检查；另复核手机开发／构建各 23 组检查。覆盖 375／768／1180／1440、显式浅色展示、弹窗焦点／Escape、草稿保留、申请与批准、首次连接分离、过期／拒绝、取消／撤销待核对以及不可用原因。

未新增 npm 依赖、生产 UI、IPC、Bot 服务或正式移动端功能。现有主工作区正在修改的 Bot／模型恢复等代码均未改动；只读取桌面 token 与 CSS。原生相机、安全存储、云端配对入口、设备授权和真正撤销仍待实施，不能把本稿的本机状态验证当成安全协议验收。构建仍有既有 SDK 共享块超过 500KB 的提示。
