# Hemi 移动端视觉交互稿 v1

2026-10-23。面向已经在桌面端初始化 Bot 的用户，手机首版只连接和使用 Bot。沿用现有浅色对话展示，iOS 优先，交互结构同时适配安卓；没有新建账号、手机端部署、语音或多 Bot 管理入口。

## 预览

[打开手机交互稿](http://127.0.0.1:5175/?scene=conversation) · [PC 设备配对交互稿](http://127.0.0.1:5175/desktop.html?scene=settings) · [PC 交互说明](DESKTOP.md)。这是本机开发预览地址，服务关闭后需重新启动；不提供公网访问。

```sh
npm run build:sdk
node docs/design/mobile/v1/serve.mjs
```

浏览器打开命令输出的地址。桌面端左侧可切换 16 个场景，右侧显示交互说明及“模拟手机断线”“完成当前演示任务”；手机宽度通过顶部“切换场景”打开评审目录。评审目录、手机外框和右侧说明不属于正式应用。桌面评审使用固定 390×844 逻辑画布，外加 8px 装饰边框；空间不足时整机等比缩放，标注当前预览百分比，不单独压缩手机高度。手机宽度直接使用实际视口。

构建和验收：

```sh
node node_modules/vite/bin/vite.js build --config docs/design/mobile/v1/vite.config.mjs
node docs/design/mobile/v1/verify.mjs
```

PC 配对专项验收使用 `node docs/design/mobile/v1/verify-desktop.mjs`，覆盖设置入口、顶部待确认、双端核对、设备列表和回执待核对。队列布局专项使用 `node docs/design/mobile/v1/verify-queue.mjs`，覆盖触摸视口、短屏、折叠、长文字、内部滚动、编辑撤回、暂停继续及离线恢复。

构建输出在 `.visual/workflow/mobile-design-v1-built/`，包含手机 `index.html` 和桌面 `desktop.html`；测试会分别启动和关闭独立开发服务、静态预览服务及浏览器。供人工评审的 `serve.mjs` 服务独立保留。

## 视觉方向

采用现有 Hemi 的白、近中性灰和墨色，鼠尾草绿只表示品牌与在线状态，琥珀色表示断线或待确认。色值与现有 token 一致：画布 `#ffffff`、外围 `#f6f6f5`、正文 `#1a1a19`、次要文字 `#696966`、状态 `#566e5d`，浅色分隔 `#e9e9e7`。字体沿用系统中文字体，正文保持现有 SDK 字号，移动端正文 14px、会话列表 13px、常规标题 16px、辅助文字 12–13px；引导页与文档主标题最高 22px。编辑框保持 16px，以免 iOS 聚焦时自动放大；占位提示为 14px。主要触摸操作至少 44px，缩小字号不缩小点击区域。视觉图标以 18px 为主，抽屉行高 48px，头像 28px；列表字号与 PC 侧栏的 13px 对齐，移动正文较 PC 默认的 15px 小一档。字号覆盖仅作用于交互稿宿主，SDK 源码未改。

手机布局是“顶部快捷导航 → 消息阅读区 → 待发送区 → 固定输入区”，默认进入当前对话。顶部依次为会话抽屉、新对话、当前标题／模型、工作目录和 Bot 连接；模型与目录打开底部面板。

会话列表改为左侧抽屉，宽度约为手机内容区的 82%，主页面向右让出位置并保留一部分可见区域。抽屉有搜索、新对话、置顶／最近列表，底部固定 Bot 身份与连接设置。点遮罩、Escape 或左滑收起；在主页面左边缘右滑打开。键盘焦点限制在抽屉内，收起后返回入口；开合不卸载对话流，不清理草稿或改变消息滚动位置。新建会话相互独立，首条输入用作列表标题；各会话分别保留草稿、模型与目录，断开 Bot 连接则影响全部会话。

文件使用独立预览页，一条 Bot 主路径不额外拆成多个底部 Tab。图片参考用于布局与交互结构，颜色、消息样式与功能范围沿用 Hemi；没有加入参考图中的通话、语音、定时任务等入口。安卓原生返回键及系统边缘返回手势冲突仍需接入验证。

消息、Markdown、思考和工具过程、文件入口、消息编辑以及队列直接使用 `@hemi/conversation-flow`，没有另外手画一套消息组件。手机队列隐藏桌面拖动与直接运行入口，保留编辑、撤回、暂停与继续。队列和草稿共用一个输入区外框，中间用细线分隔；待发送单行 44px、正文 13px，编辑／撤回点击区域仍为 44px。长内容最多显示两行摘要，编辑时查看全文；只在待发送列表内部滚动，折叠标题、暂停操作和输入框保持可用。通过宿主布局容器调整到手机宽度，不修改 SDK 源码。

## 扫码连接自己的新设备

新增 [生成配对码](http://127.0.0.1:5175/?scene=pair-share)、[扫码连接](http://127.0.0.1:5175/?scene=pair-scan)、[原设备确认](http://127.0.0.1:5175/?scene=pair-confirm) 和 [已连接设备](http://127.0.0.1:5175/?scene=devices)。首次连接页有扫码入口，已连接设备的 Bot 设置里有“连接新设备”。

原设备和新设备分别连接云端 Bot，支持手机流量与跨网络，无需处于同一局域网。配对邀请 2 分钟有效，只完成一次设备登记；扫码不会直接获得 Bot 权限。原设备核对双方验证码后明确允许，设备名称不作为可信身份证明。配对码过期／取消／被使用后移除；设备通过独立身份连接，可以分别撤销。关闭时向 Bot 取消待处理邀请；若取消回执未知，隐藏旧码并核对服务端状态，最终以 Bot 的到期／消费状态为准。具体需求、泄露威胁和现有 SSH 的改造边界见 [扫码配对方案](../bot-device-pairing.md)。

右侧评审按钮用于模拟“新设备扫码”“配对码过期”“原设备允许／拒绝”等事件，不属于正式产品。手机宽度可通过评审目录切换到对应状态。二维码是可解码的 `hemi-demo` 演示载荷，无法连接真实 Bot；扫码取景示意不会调用相机。配对状态和设备列表仅在当前页面内模拟，生产的云端 HTTPS 配对入口、密钥登记、Bot 鉴权和撤销均尚未实现；该入口计划集成在现有 Bot，无需独立公网中转服务。

## 页面与状态

| 场景 | 主要操作与反馈 |
| --- | --- |
| [生成配对二维码](http://127.0.0.1:5175/?scene=pair-share) | 已连接设备创建邀请；短时单次，扫码后还需要原设备确认。 |
| [扫码连接 Bot](http://127.0.0.1:5175/?scene=pair-scan) | 新设备先核对 Bot 信息，再发起申请等待确认。 |
| [确认新设备](http://127.0.0.1:5175/?scene=pair-confirm) | 双端验证码，明确核对后允许；可拒绝，过期不能批准。 |
| [已连接设备](http://127.0.0.1:5175/?scene=devices) | 独立设备列表，确认后撤销指定设备；缓存无法远程收回。 |
| [连接已有 Bot](http://127.0.0.1:5175/?scene=connect) | 扫码连接入口；或手动填写地址、账号和端口，导入认证后继续。手动填写的地址传到信任面板和连接设置。 |
| [核对主机身份](http://127.0.0.1:5175/?scene=trust) | 完整演示指纹，明确“信任并连接”或返回修改。 |
| [会话列表](http://127.0.0.1:5175/?scene=history) | 左侧抽屉；搜索、新建、置顶／最近列表、固定 Bot 连接入口。 |
| [对话与交付](http://127.0.0.1:5175/?scene=conversation) | 正文直接阅读，过程默认折叠，文件入口留在对应回复。 |
| [执行中的任务](http://127.0.0.1:5175/?scene=running) | 正在执行时仍可输入下一条；发送和停止分别呈现。 |
| [继续输入与排队](http://127.0.0.1:5175/?scene=queued) | 待发送项可编辑、撤回。停止后队列暂停，明确继续才再派发。 |
| [等待你的确认](http://127.0.0.1:5175/?scene=permission) | 底部确认面板，显示命令、位置与影响；拒绝或允许这次，无自动放行与手机端倒计时。 |
| [断线与本机待发送](http://127.0.0.1:5175/?scene=offline) | 缓存继续可读；新输入先保存在手机，重连核对后再投递。切换或新建会话仍保持离线。停止与编辑等命令不可离线提交。 |
| [提交结果待核对](http://127.0.0.1:5175/?scene=unknown) | 阻止重复发送，保留原稿；确认受理只清理对应草稿版本，用户后来写的内容保留。 |
| [文件预览与保存](http://127.0.0.1:5175/?scene=file) | 阅读、系统保存与分享；返回后回到同一会话。预览提供可实际下载的内置示例文件。 |
| [Bot 连接设置](http://127.0.0.1:5175/?scene=settings) | 查看服务器、重新连接、修改连接、断开手机连接。断开前说明云端任务不因此停止。 |
| [主机身份发生变化](http://127.0.0.1:5175/?scene=identity) | 阻断自动连接，返回设置核对；不提供跳过检查的按钮。 |

建议评审路径：

1. 连接已有 Bot → 导入演示认证 → 核对身份 → 主对话 → 左侧抽屉切换 → 文件预览 → 保存 → 返回。
2. Bot 设置 → 连接新设备 → 模拟新设备扫码 → 核对双端验证码 → 允许 → 已连接设备 → 撤销；另体验过期、拒绝与无效配对码。
3. 执行中继续输入 → 队列编辑／撤回 → 停止 → 继续；再体验断线输入、重连核对和提交结果待核对。

## 本稿边界

这是可运行的交互稿，不是移动端生产功能。服务器、指纹、私钥导入、上传、模型目录、文件夹、运行和权限均为本机演示数据；不会读取真实私钥、连接 SSH、调用模型或执行展示的命令。输入内容只进入 `hemi-mobile-design-v1` 命名空间：草稿用 localStorage，本机待发送记录用 sessionStorage。评审场景切换会重置模拟运行事实，刷新不会恢复真实云端任务；页面内的模拟任务可以在会话切换期间继续。新建列表与模型／目录偏好仅保留在当前预览页面中，不模拟完整云端持久化。

文件下载是内置合成文本的真实浏览器下载；分享在可用时调用 Web Share，不可用时复制内容。自动验证覆盖下载与剪贴板回退，原生系统分享、文件选择、安全存储、SSH、手机后台恢复及 iOS／Android 真机仍需正式接入验收。手动连接先画私钥认证；新增的设备配对为待实现方案，不能理解为已支持真实无凭据扫码连接。

底部授权面板展示 Bot 的无限等待语义，当前为宿主演示面板；后续应让 SDK 的移动端授权部件支持相同容器与等待状态，不把确认状态另存成产品逻辑。

本稿只新增 `docs/design/mobile/v1/` 下的文件，没有修改生产应用、SDK、依赖或主工作区正在进行的 Bot 修复。复用项目已有字体、图标与组件；版权及许可沿用根目录 `THIRD-PARTY-NOTICES.md` 和 SDK 包内通知。
