# Hemi 对话流 SDK 抽离需求

| 项目 | 内容 |
| --- | --- |
| 版本 | 1.0 |
| 日期 | 2026-10-22，Asia/Shanghai |
| 状态 | 设计草案，供实现与评审 |
| 目标 | 保留现有展示与交互，抽出由宿主提供数据和能力的纯前端对话流 |
| 接入环境 | Web、现有 Electron 桌面、iOS WebView、Android WebView |
| 源码基线 | `4e6f51707269cd4152ed7da9cd4fc00c21ca12c1` 加本次核对时的工作树；包含尚未提交的后台命令展示调整 |
| 配套方案 | [技术方案](../technical/conversation-flow-sdk.md) |

Hemi 将现有消息流抽成可独立安装的前端组件 SDK。宿主传入展示数据，SDK 渲染相同的消息、执行过程和卡片；文件、链接、剪贴板等环境能力通过统一 API 注入。业务操作通过动作回调交给宿主，更新后的数据再由宿主传回。SDK 可以只使用本地模拟数据运行，不要求启动 Hemi、Bot 或模型服务。

## 1 已确认的边界

| 用户要求 | 约束 |
| --- | --- |
| 保留现有效果 | 以当前工作树的普通对话为基线，保留结构、顺序、样式、状态和交互，不在抽离中重新设计一套聊天界面 |
| 纯前端对话流 | SDK 管理展示和局部 UI 状态；消息、任务、授权等业务状态由宿主提供 |
| 少量公开 API | 一个对话流主组件、统一 Host 接口、一个业务动作回调和一个滚动句柄；内置部件可按相同契约单独组合以保留宿主布局 |
| 宿主能力注入 | 同名方法具有相同参数、返回值和失败语义；环境差异留在适配器内 |
| 多端复用 | 各端使用同一份 React Web 组件；移动端通过 WebView 承载，原生壳提供适配器 |

纯前端指不依赖 Electron、Node.js、Hemi 运行时、模型接口或必需的外部服务。React、Markdown、图标和虚拟列表属于前端依赖；依赖及其许可证须随包正确声明。资源 URL 的实际加载由浏览器或宿主提供的能力完成，不因此把文件获取或模型连接加入 SDK。

本次交付需求与方案。SDK 实现、桌面迁移、移动壳、应用上架和公开 npm 发布分别在后续开发阶段交付。

## 2 范围与相邻功能

| 区域 | SDK 范围 | 宿主范围 |
| --- | --- | --- |
| 对话消息 | 用户消息、助手消息、流式内容、错误、附件及引用回显、复制和编辑界面 | 消息来源、历史加载、发送、编辑后重跑、失败重试 |
| 执行过程 | 思考与工具分组、摘要、耗时、展开、子任务紧凑行 | Agent、工具执行、任务调度、完整任务档案查询 |
| 授权 | 当前会话的确认卡、队列提示、禁用和失效状态 | 权限判定、有效期、受理与撤销；跨会话导航及全局提醒 |
| 工作流 | 现有行内卡片、参数与人工输入表单、进度、操作反馈 | 定义和模型数据查询、草稿保存、开始、停止、继续、版本校验、工作流编辑器 |
| 文件 | 文件卡、缩略图、错误与重试、统一资源菜单 | 文件查证与读取、下载、分享、打开程序、定位目录 |
| 预览 | 流内展示及“查看文件／过程”的动作入口 | 桌面右侧预览、移动端预览容器及文档解码器；继续使用现有宿主预览能力 |
| 页面外壳 | SDK 自有滚动容器、加载提示和回到底部 | 会话侧栏、顶部工具栏、主输入框、待发送队列管理、模型设置、记忆提醒、语音、启动主题画面 |

预览容器位置随宿主变化。流内卡片、内容顺序和操作含义保持一致；本需求不把桌面三栏外壳作为手机布局。消息编辑用到的局部文本框属于对话流，主发送输入框继续由宿主组合。

授权卡和运行摘要由 SDK 提供相同的纯展示部件。主组件可以默认组合；桌面可以将部件放在现有授权区和队列／输入区附近，保持原来的先后与层级。该组合方式不引入业务读取，不将所有外围控件强行搬进消息列表。

[Bot 与普通对话的复用约定](../design/cloud-bot/conversation-reuse.md)覆盖完整对话页面；本 SDK 是其中的消息流部分。Bot 的附件上传、会话列表、输入区和模型同步仍按 Bot 需求完成，不因抽离 SDK 被删减。

## 4 功能要求

### R01 独立接入

安装包后可在独立 React Web 页面引入组件、类型和样式。只传展示数据即可看到消息流；不注入能力时仍能展示内容。包不得要求 Hemi 的目录别名、应用全局 CSS、Tailwind 构建配置、IPC 全局对象或服务器地址。SDK 不安装全局桥，不向宿主全局注册工作流事件。

### R02 受控数据与稳定身份

宿主提供已经排序的消息及其 parts。每个消息、分段、工具调用、任务、授权和资源有稳定身份；同一对象流式更新时沿用身份。SDK 不按时间戳重新排序，不根据正文猜测任务结果，不补造业务状态。环境、会话和展示代次共同界定作用域，两个组件实例相互隔离。

### R03 流式展示

宿主通过更新同一消息／part 的累计内容和状态驱动流式展示。SDK 不要求消费 token 协议，不负责请求或重连。只有明确标为活动尾段的内容显示动态提示；中断、停止、历史回看与正常完成分别展示。旧档由 Hemi 适配器转换，SDK 不承担档案迁移。

### R04 保留视觉与隔离样式

同一数据、主题、容器尺寸和输入方式下，抽离前后结构、文字、颜色、间距、图标和交互一致。桌面取当前实际样式为参照，不只复制一个 CSS 文件。SDK 提供自身 token 默认值、重置规则和作用域，菜单及弹层也受相同主题约束，不修改宿主的 `html`、`body` 或全局 token。

跨端共用组件和响应式规则；系统字体字形和抗锯齿差异允许通过视觉评审明确记录，不能借此放过内容缺失、换位、溢出或操作回归。

### R05 滚动与局部状态

SDK 只管理自身的一个主滚动容器，宿主分配有界尺寸。首次打开和宿主明确发起的新消息沿用当前定位策略；历史前插保留阅读锚点。用户上翻后，后续文字、图片解码和计时更新不得强制跳底。编辑、选择或聚焦的行按现有规则保持可操作；展开状态在虚拟卸载后恢复，跨作用域不复用。

公开句柄支持滚动到底部和定位已加载消息。未加载目标返回可识别结果，由宿主决定是否加载历史；不触发隐式网络请求。

### R06 Host API

统一接口覆盖复制、外部链接以及资源解析、读取和资源动作。每个方法返回 Promise 和统一结果类型，具有明确取消、失败和不支持语义。同名操作保持同一含义，例如“保存”不能在手机上静默变成“分享”。平台实际可用的动作通过能力声明和资源动作列表提供。

适配器可以基于浏览器 API、Electron IPC、Capacitor 或自定义原生桥。SDK 本身不依赖这些实现。没有能力时保留内容并说明不可用原因；不得出现点击后静默无响应。

### R07 业务动作回调

编辑重发、重试、停止、授权决定、工作流配置／草稿／开始／停止／继续和预览请求通过一个类型明确的 `onAction` 回调发送。回调携带作用域、对象身份、请求身份及必要的版本信息。SDK 可以显示提交中与失败反馈，但只有宿主回传的数据能够表示正式任务、授权或工作流状态已改变。

同一按钮等待期间防重复提交。未获确定回执时显示待核对，不自动重发有副作用的动作。历史或失效交互禁用；任务是否仍有效由宿主再次核对。

取消一次前端请求只结束相应读取或等待，不自动发送停止任务、拒绝授权或取消工作流。用户明确停止时才发出对应业务动作。

### R08 文件与资源

资源引用包含宿主命名空间内的稳定标识和内容版本。路径可作为显示信息或待解析链接，但不能直接成为 SDK 的读取权限。缩略图在靠近视口时按需加载；请求和缓存绑定作用域、资源身份、版本和读取用途。

切换会话、更新版本或卸载时取消读取；即使宿主无法即时中止，也要丢弃旧回执并释放资源。读取失败、离线、文件不存在和无权限提供反馈和重试入口。撤销或拒绝文件操作不改变消息内容。

### R09 生命周期

宿主通过属性声明当前实例是否活跃。后台或隐藏实例暂停非必要计时与测量，恢复时从当前数据和时间重新计算，不倒计时补发授权动作。卸载后清理订阅、观察器、计时器、资源句柄和自身浮层。导入 SDK 时不访问宿主全局，也不产生网络和设备副作用。

### R10 移动与无障碍

Web、桌面和两种移动 WebView 使用同一内容结构；以容器宽度和输入方式适配，不为各平台另写消息渲染器。核心功能不依赖 hover：触屏提供明确的更多操作入口，保留系统文本选择，长按不能与选择冲突。触屏操作目标约 44px，文字和表单在放大后可阅读。

键盘可访问展开、编辑、菜单、重试和授权；焦点只在当前实例内管理。SDK 不捕获全应用快捷键。保留减少动态效果偏好和读屏状态提示，流式文字不按每个字符播报。

宿主负责安全区、键盘避让和 WebView 尺寸；避免宿主与 SDK 同时缩减键盘高度。

### R11 展示数据完整性

工作流模型选项、参数标签、表单、版本、当前节点、确认事项和操作条件由宿主转换为展示数据。SDK 不因缺少直接查询能力而把现有卡片降为标题或通用 JSON。SDK 发布的类型只包含展示与交互所需字段，不重新导出整份应用协议或工作流执行引擎。

### R12 包与许可证

首版使用一个包组织组件、展示类型和样式，保持 React 和 React DOM 为 peer dependencies。前端依赖从当前锁定版本起步，具体发布名、兼容范围和包体在实现阶段冻结。产物独立于当前 Vite 别名，可被普通构建器消费；提供类型声明和自包含 CSS。第三方声明覆盖随包交付的 Markdown、图标、虚拟列表等实际依赖及资源。

## 5 多端交付标准

| 环境 | 共享内容 | 必须验证的宿主差异 |
| --- | --- | --- |
| Web | SDK 的组件、样式、数据与动作契约 | 浏览器权限、用户手势、链接打开、资源 URL 生命周期、独立构建 |
| Electron | 同一 SDK；现有页面提供展示数据 | 真实 IPC 的复制、文件查证、打开程序、定位目录；Vite 与构建 renderer |
| iOS | 同一 SDK 运行在 WebView | 真机触控、选择、原生剪贴板与分享／保存、键盘、安全区、前后台切换 |
| Android | 同一 SDK 运行在 WebView | 真机触控、选择、系统返回、内容 URI、原生剪贴板与分享／保存、键盘和恢复 |

纯 SwiftUI、Compose 或 React Native 原生视图接入可以沿用契约，但它们需要各自的渲染实现，不属于这份 React Web SDK 的“同一份 UI”交付。

WebView 截图和浏览器设备模拟只能证明对应渲染行为。两种移动端完成原生壳和真实能力验证后才能标为已支持；设计阶段不提前标记通过。

| A13 | 样式与浮层隔离 | 有宿主重置样式、两个不同主题实例、宿主弹窗时，内容、菜单和焦点不串扰 |

每轮实施记录被测 commit、必要的工作树源文件摘要、系统／浏览器／WebView 版本、命令、截图、适配器类型和未覆盖项。新增 renderer 依赖后生成并复核第三方声明。验证扩展到失败或未解决的问题，不默认运行全部应用测试。

## 7 交付次序

1. 固定当前工作树展示基线和模拟场景，确定公开数据、动作与 Host 契约。
2. 抽出 SDK，在独立离线示例中保留全部内置展示；用消费项目验证安装包和 CSS。
3. 让普通桌面对话接入同一 SDK，完成现有 IPC 和两个 renderer 的真实回归。
4. 为 Web、桌面 Bot 和移动壳提供同名接口实现；SDK 不随之加入连接或任务调度。
5. 分别验收 Web、iOS、Android，记录每种宿主真实具备的能力。

每一步都有单独完成条件。桌面接入前 SDK 不要求 Bot 已实现，移动验证也不把浏览器设备模拟当作原生桥验证。
