# Hemi 原生 pi-memory 共享记忆重构需求

| 项目 | 内容 |
| --- | --- |
| 版本 | 1.2 |
| 日期 | 2026-10-27（Asia/Shanghai） |
| 状态 | 已按最新确认简化并复验；尚未正式发布 |
| 目标 | Hemi 直接使用原版 pi-memory，重构自身的会话运行、界面和 Bot 接入，替换自研记忆系统 |
| 已确认的记忆范围 | 每个桌面实例一个共享记忆库；每个 Bot 实例一个共享记忆库 |
| 兼容要求 | 重构，不要求旧版本、旧记忆格式和旧记忆接口兼容 |
| 核对基线 | `4af7ccbe70f9ffcd13854a8868ca034825e6e76d` 加核对时工作树；Pi SDK 1.3.0、已安装 pi-memory 0.4.2 |

本文定义新的记忆产品与运行方式。实现时，记忆正文、原生文件工具、上下文注入和摘要行为由上游插件负责；Hemi 负责执行会话、展示结果、管理执行环境。

本文中的“已确认”仅指第 1.1 节用户明确作出的决定。其余条目是为落实这些决定提出的首版方案，包括子 Agent 分工和管理界面的简化，不冒充已经逐项确认的产品要求。

## 1 目标与边界

### 1.1 已确认的决定

| 决定 | 约束 |
| --- | --- |
| 原版插件直接使用 | 通过 Pi SDK 原生加载官方 pi-memory 包，保留其工具名称、参数、结果和数据格式 |
| 不增加适配层 | 不建设 Hemi 记忆后端抽象、MemoryClient、工具参数转换、存储包装或第二套记忆协议 |
| 不修改插件 | 不维护 fork，不修改 node_modules，不使用补丁、模块全局变量修改或运行时 monkey patch |
| 重构 Hemi | 会话调度、执行进程、生命周期、权限、设置页和 Bot 可按原生插件的要求重新设计 |
| 每个桌面／Bot 一个库 | 同一运行实例内的会话与项目共享记忆；不同运行实例相互独立 |
| 无旧版本兼容要求 | 不保留双引擎、旧接口代理、旧数据格式读取或运行时回退 |
| 自动整理默认开启 | 正常结束会话时按原生语义整理日志，不提供单独开关 |
| 不交付大型搜索组件 | 不部署 qmd、额外 Node 或 GGUF 模型，不显示安装／搜索状态入口 |

### 1.2 本期交付范围

包括桌面普通对话、Bot 主会话、原生记忆工具与生命周期、记忆查看入口、自动整理说明、运行状态、旧实现清理和端到端验收。手机使用所属 Bot 的记忆能力，不在手机端安装记忆引擎。

本期不实施旧记忆导入或迁移，不建设跨桌面、桌面与 Bot、Bot 与 Bot 的记忆同步。此处的“不兼容”限于被本需求替换的记忆能力；不会据此清空用户的会话、模型、附件或其他应用数据。

旧记忆文件保持原位但不被新引擎读取、注入或索引，不自动删除。新记忆从独立的新目录开始。开发和验收均使用临时数据目录，不读取真实用户记忆。

### 1.3 与现有文档的关系

实施本重构时，本文取代原有个人／全局／工作区分域记忆、Hemi 自研工具、任务终态提炼及记忆条目管理要求。原 README 中的三类记忆说明应随功能交付更新。

[云端 Bot 需求](cloud-bot.md)中的执行位置、持久受理、断线续跑、授权、会话草稿和文件能力继续适用；其中 R-06 的“不同会话独立并行”继续保留；R-04 已根据原版插件与实际 SDK 的验证结果更新，不引入整库主会话排队。

## 2 记忆归属与数据模型

### 2.1 运行实例的定义

| 场景 | 使用的记忆库 |
| --- | --- |
| 同一桌面用户数据目录下的窗口、会话和项目 | 同一个桌面记忆库 |
| 桌面主 Agent 操作普通 SSH 工作区 | 桌面记忆库；记忆归属由 Agent 运行位置决定 |
| 同一 Bot 下的全部会话和工作目录 | 该 Bot 的共享记忆库 |
| 桌面、手机连接同一个 Bot | 同一份服务器记忆，不按客户端创建副本 |
| 不同桌面用户数据目录、不同 Bot 实例 | 各自独立的记忆库 |

共享记忆库包含个人事实、长期偏好、约定及项目相关经验。项目适用条件可以写入正文，但它不构成技术上的项目隔离；切换项目不会切换记忆库。项目中的 `AGENTS.md` 等仍按项目上下文规则加载。

### 2.2 原生文件

首版建议桌面使用 `<userData>/pi-memory/`，Bot 使用 `<botDataDir>/pi-memory/`，由执行进程启动前设置 `PI_MEMORY_DIR`。实际路径必须属于对应运行实例，不能默认落入用户已有的 Pi CLI 记忆目录。

| 文件 | 产品含义 |
| --- | --- |
| `MEMORY.md` | 共享的长期记忆 |
| `daily/YYYY-MM-DD.md` | 插件生成或追加的每日记录 |
| `SCRATCHPAD.md` | 待办与便签 |
| `recovery/*.json` | 插件生成的删除恢复记录 |

以上以[原版插件文件模型](https://github.com/jayzeng/pi-memory/tree/v0.4.2#file-layout)为准。Hemi 不再创建 `USER.md`、工作区记忆子库、条目版本表、来源账本、跨文件事务日志或另一份权威记忆数据库。不建设检索索引或下载检索模型。

## 3 功能要求

### R-01 原生加载与单一所有者

Hemi 使用 SDK 支持的扩展加载入口，加载锁定版本的原版 pi-memory。加载后实际执行上游注册的处理函数；不复制插件代码到 Hemi，不用同名自研工具替换原生工具。

删除现有记忆投影与桥接注册，保证每个主会话只有一套记忆工具和一条记忆注入路径。插件的原生上下文截取、快照刷新和容量规则作为本版行为，不继续叠加旧的 Hemi 投影预算或缓存。

通用进程通信、权限判定、文件预览和 Bot 传输可以承载会话事件与原始文件；不得在这些入口内重新实现记忆存储、生成自研记忆实体，或把旧 `listEntries`／`mutateEntry` 接口包装到插件之上。

### R-02 共享与隔离

用户在桌面会话 A 保存的长期记忆，可以在同一桌面的新会话 B 中读取和使用；切换模型、工作目录、新建会话或重启应用不会建立另一份记忆库。Bot 按相同规则工作。

桌面记忆与 Bot 记忆不自动复制、合并或互相检索。查看入口始终标明“此桌面”或当前 Bot，客户端切换目标后不得继续展示成另一实例的实时内容。

新建的执行进程应在加载插件前固定记忆目录及配置；运行期间不得通过改写父进程环境变量来切换某个已加载插件的记忆归属。

### R-03 主会话与子 Agent

首版方案只在处理用户对话的主 Agent 中加载记忆插件。主 Agent 直接使用 `memory_write`、`memory_read`、`memory_forget`、`memory_restore`、`scratchpad`，名称与参数保持原样。通过 SDK 公开的 `excludeTools` 排除依赖 qmd 的 `memory_search` 和 `memory_status`；不修改插件注册逻辑。

子 Agent、验证会话及模型连接探测不加载记忆插件。子 Agent 从主 Agent 派发的任务上下文取得所需事实，由主 Agent 结合用户意图决定是否调用原生工具保存。工作流存在独立根会话时，也按主会话规则纳入所属实例的运行调度。

只读会话不因压缩或退出钩子写入记忆。工具白名单、门控和角色声明按新的分工调整，不能只屏蔽 `memory_write` 而仍允许插件的生命周期写入。

### R-04 会话执行与同库并发

每个桌面／Bot 的主会话在该实例的同一个 Node 进程中运行，共享固定的插件目录配置；不同实例使用不同进程和数据目录。禁止多个 Host 同时控制同一目录，禁止运行期间切换某个已加载插件的目录。

保留现有的跨会话并发、每会话持久队列、授权和交互资源控制。插件当前版本的记忆文件读改写临界段使用同步文件操作，在单个事件循环内完成；Hemi 不增加记忆工具锁、转发工具、存储代理或整库主运行队列。异步摘要完成后的原生文件写入也必须位于同一所属进程。

原草案曾建议“每会话隔离进程＋整库执行排队”。实现探针验证了 SDK 的扩展工厂缓存、原版插件的同步文件临界段及公开的逐轮快照模式后，采用上述同进程方案。实际 SDK 下 40 次并发写入、生产桌面两会话同时提交均保留了全部内容；依据与适用限制见[技术记录](../technical/native-pi-memory.md)。此决定保留原有并发体验，不代表上游插件可被任意多进程同时写入同一库。

等待授权、子任务和后台结果时沿用现有根运行归属；停止时等待所属工具与后台执行收口。进程异常退出后恢复已有持久受理状态，不自动重放结果未知的写入或其他副作用。

### R-05 跨会话的记忆新鲜度

通过插件公开配置 `PI_MEMORY_SNAPSHOT=per-turn`，使每次模型回合启动时读取当前共享库。A 会话写入后，B 的下一轮及 A 再次运行均取得更新；Hemi 不自行拼接记忆 system 消息，也不使用插件测试专用的状态修改函数。

同一次已发出的模型请求保持其原生上下文；共享不意味着改写正在生成的请求。需要主动核对内容时使用原生 `memory_read`。

### R-06 原生生命周期与退出摘要

Hemi 必须完整承接 SDK 的原生扩展生命周期，使用实际行为对应的事件和原因。当前仅调用 `dispose()` 的释放路径需要重构，不能把释放监听器误认为完成了插件退出钩子。

| 事件 | 要求 |
| --- | --- |
| 新建或恢复执行会话 | 完成原生扩展绑定和启动事件后再发起模型请求 |
| 单轮回答结束 | 保留原生会话语义，不人为触发退出摘要 |
| 切换页面、折叠窗口、客户端断开 Bot | 不作为云端或后台执行会话退出 |
| 运行实例重载、恢复、替换 | 使用 SDK 对应的过渡生命周期；不能伪装成用户退出以强制总结 |
| 上下文压缩 | 让插件原生压缩钩子执行，不再额外写一份 Hemi 交接记录 |
| 实际正常关闭 | 在会话上下文仍可用时执行并等待原生关闭钩子，再释放进程 |
| 崩溃或强制终止 | 报告收尾未确认；不承诺摘要已保存，不补造成功结果 |

自动摘要采用插件的会话退出语义，替换旧的“每个任务终态再提炼一次”。固定启用退出摘要，不提供设置开关；执行进程使用插件公开配置 `PI_MEMORY_EXIT_SUMMARY=1`。每个实际关闭事件只派发一次；不扫描全部历史会话补写摘要。

Host 对正常关闭设置整体等待上限，首版建议 30 秒；超过上限后允许终止执行进程并报告未确认的收尾。插件自身的摘要超时与过渡跳过规则继续生效，不用自研模型调用替代失败摘要。

### R-07 模型、认证与用量

SDK 中登记的模型、供应商和凭据必须足以让插件自行取得当前模型或公开配置指定的摘要模型。摘要请求使用插件原生路径，Hemi 不截获并改写成现有 `auxiliaryCall` 提炼任务。

实际验证本项目使用的模型类型和认证方式。模型不支持插件使用的请求参数、缺少可解析凭据或接口不可达时，基础记忆工具按其实际结果继续工作，不宣称摘要已经保存，也不宣称所有能聊天的模型必然能执行插件摘要。0.4.2 的关闭钩子不返回逐次摘要失败原因，因此查看页只说明自动整理行为，并明确结果以每日日志为准；不为补齐错误回执改写插件或拦截摘要调用。

费用和用量只展示可观测到的事实。通用模型观测能够覆盖摘要调用时，标明它的来源；不能取得其用量时说明统计未包含插件摘要，不填零、不把不完整数据称为总用量。禁止为补统计另造记忆模型调用链。

### R-08 记住、遗忘与恢复

用户通过对话表达记住、纠正、忘记或恢复的意图，主 Agent 调用插件原生工具；界面沿用真实工具过程，只有收到成功结果后才能确认已完成。

采用[原版工具语义](https://github.com/jayzeng/pi-memory/blob/v0.4.2/index.ts)：长期记忆按原生追加／覆盖方式维护，遗忘按匹配文本及指定文件处理，恢复使用插件给出的 recovery ID。不得将一次多处匹配的删除包装成“只删了某个自研条目”。

遗忘不是清除所有历史副本：会话历史、其他日志和恢复记录按原生规则保留；恢复记录本身包含被删除的内容。旧版的来源撤销、跨日志关联清理、强制过期投影及防止旧材料再次提炼的保证不再作为本版功能，不补回相同的自研账本。

### R-09 记忆查看与管理入口

桌面设置保留“记忆”入口，内容围绕原生文件重做。Bot 设置提供同样的服务器记忆入口；手机展示当前 Bot 的相同数据。

首版页面包括所属实例、长期记忆、按日期浏览的日志、待办原文、删除恢复记录，以及自动整理说明。采用 Markdown／文本查看，不把正文解析成旧版条目卡片。首次使用显示空库，不提供个人／全局／项目切换。

新增、修改、遗忘、恢复及待办操作统一在所属实例的对话中完成。查看页可以将用户选择的操作带入输入框，用户发送后走正常会话；首版不提供另一套后台记忆 CRUD，也不保留原来的原文保存、跨范围移动、条目版本和撤销接口。

查看文件使用现有通用文件预览与传输能力。Bot 只开放此功能允许的原生记忆文件，校验实例、身份、路径和文件类型；不能为展示记忆开放整个数据目录。恢复记录按用户明确查看时读取，不作为默认搜索内容。

打开页面不应隐式发起模型调用。不显示搜索组件、安装按钮、退出摘要开关或重新启动提示。离线 Bot 的缓存只读且明确标为缓存，写操作等待重新连接和正常受理。

### R-10 不交付大型搜索依赖

按用户 2026-10-27 的最新决定，本期不部署 qmd，不增加用于检索的独立 Node、原生推理库或 GGUF 模型，也不提供手动／自动安装入口。

原版记忆保持 `PI_MEMORY_SNAPSHOT=per-turn`，每轮读取同库文件。设置 `PI_MEMORY_NO_SEARCH=1` 和 `PI_MEMORY_QMD_UPDATE=off`，关闭隐式检索与后台索引／嵌入。用 SDK 原生工具排除规则隐藏两个 qmd 工具，不制作替身，不实现备用关键词搜索。

插件原有的可选 qmd 启动探测可以保留；即便系统已安装 qmd，也不能触发嵌入模型下载。隔离可选 qmd 配置目录，避免影响用户自己的 qmd。不开启任何新的兼容路径，不删除用户已有的外部搜索数据。

### R-11 Bot 与多客户端

Bot 在服务器执行与桌面相同的原生插件加载和运行流程；将原版插件纳入云端组件。记忆文件、模型调用和摘要均在服务器完成。

关闭桌面、手机退后台或断开 SSH 不影响已受理的 Bot 主运行和记忆归属。客户端重连后从服务器取得真实结果，不能将本地展示缓存作为记忆权威内容上传。

多个客户端同时发给同一 Bot 的输入由服务器持久队列和控制权规则处理；同一会话保持既有串行受理，不同会话在所属 Host 的同一进程中并发运行。客户端不能另起进程直接写共享库。读取记忆和操作恢复记录沿用 Bot 身份认证，切换实例时清理或隔离缓存。

### R-12 配置与故障处理

记忆页不提供配置项。原生环境在执行实例启动时固定，自动整理启用、检索及后台嵌入关闭；不得按某个会话改写另一个实例的环境。

记忆目录不可写、文件无法读取和插件加载失败应能分别诊断。摘要诊断按 R-07 的上游可观测边界展示；关闭钩子返回不等同于摘要保存成功。插件或核心记忆不可用时不得继续显示“记忆正常”，也不能自动切回旧引擎。诊断记录不包含记忆正文、凭据或未经脱敏的模型请求。

### R-13 无旧版本兼容与旧实现清理

新引擎不读取旧的 `USER.md`、旧 `MEMORY.md` 管理块、`control.json`、工作区记忆目录、来源序号、撤销记录和提炼队列；不提供旧格式转换器、迁移开关或双写阶段。新目录首次为空，旧文件不自动删除。

旧记忆 IPC、共享类型、preload 方法、工具参数、设置项和通知协议直接移除，由新界面及原生工具行为替代。桌面、Bot 与手机涉及的新协议按同一发布版本协同交付；版本不匹配时要求更新，不提供旧记忆协议兼容分支。

已有会话历史仍是会话历史，不自动扫描为新记忆。新版本不得把旧记忆 tool call 按新参数再次执行；历史工具结果是否展示继续服从会话档案规则。

删除只针对本需求替换的长期记忆代码。`provider-import/login-memory` 等登录状态保存和其他用途的内存缓存不属于清理范围。

### R-14 依赖与发布

锁定实际验证过的官方插件版本及完整性，不从浮动 Git 主分支取代码。当前核对的已发布版本为 0.4.2；实施时以原始发布包和锁文件校验内容，不能只看 package.json 的版本号判断“未修改”。

桌面安装包和 Bot 运行包都应验证 SDK 能实际加载插件及其依赖，不能以开发目录存在 node_modules 作为打包通过。保留第三方版权声明，保留官方 pi-memory 的完整发布文件及版权文本，不引入搜索原生组件。

## 5 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 原版直接使用 | 发布包完整性一致；生产会话执行官方工具处理函数；无 fork、补丁、同名替身、MemoryClient 或第二套存储 |
| AC-02 | 新库与旧数据 | 放置旧记忆夹具后，新库仍为空且不注入、不索引旧内容；旧文件字节不变；没有迁移或回退路径 |
| AC-03 | 同桌面共享 | A 会话保存事实后，切换项目的新会话 B 及重启后的会话均能原生读取并使用该事实 |
| AC-04 | 运行实例隔离 | 桌面、Bot A、Bot B 的文件互不混入；同一 Bot 的桌面与手机看到同一份内容 |
| AC-05 | 原生工具 | 实际执行长期写入、日志追加、待办、读取、遗忘与 recovery ID 恢复，核对真实文件和工具结果 |
| AC-06 | 遗忘语义 | 多处匹配的真实删除范围可见；恢复保持原生行为；不宣称清除了历史、其他日志或恢复记录 |
| AC-07 | 同库并发 | 两条主会话同时提交并实际执行原生写入，全部内容保留；同会话持久队列、取消、重连与受理身份一致 |
| AC-08 | 背景与授权 | 等待授权、子 Agent、后台命令及回调保持根归属；其他会话可在同一 Host 中运行；停止后无迟到工具写入或队列死锁 |
| AC-09 | 独立运行 | 桌面与 Bot 可同时执行；一个实例等待授权或收尾，不占用另一个实例的执行权 |
| AC-10 | 快照刷新 | A 写入、B 修改／遗忘、A 再恢复的真实模型请求使用新的原生记忆上下文；无自研注入 |
| AC-11 | 子 Agent 边界 | 子 Agent、验证及模型探测会话不注册插件、不产生记忆文件或退出摘要；主 Agent 可正常保存最终事实 |
| AC-12 | 生命周期 | 页面切换和单轮结束不触发退出摘要；实际压缩、恢复、重载、正常关闭与强制终止符合 R-06，记录真实事件顺序 |
| AC-13 | 模型与费用 | 使用实际 SDK 模型登记及凭据路径完成原生摘要；失败状态和用量覆盖边界如实显示，无替代提炼调用 |
| AC-14 | 无大型依赖 | 桌面和 Bot 产物不含 qmd 部署器、平台锁、检索 Node 或 GGUF 权重，无安装接口及后台下载 |
| AC-15 | 无搜索仍可用 | 每轮原生文件快照及五种文件工具正常；两个 qmd 工具不对模型声明，后台嵌入关闭 |
| AC-16 | 记忆页面 | 开发与构建 renderer 均可查看原生文件、恢复记录及所属实例；无旧分区、条目 CRUD 或隐式模型调用；窄屏可用 |
| AC-17 | Bot 实际链路 | 经真实客户端通道到服务器执行原生工具；断开客户端后运行继续，重连结果可核对；任意路径和跨实例读取被拒绝 |
| AC-18 | 崩溃与恢复 | 杀死所属 Host 后运行可恢复为中断状态；不把不确定写入显示为成功、不自动重放；可通过实际文件重新核对 |
| AC-19 | 发布与清理 | 桌面及 Bot 产物加载官方包成功；旧生产记忆实现与协议已移除，第三方许可齐全，非记忆能力未因清理被删除 |
| AC-20 | 应用回归 | 模型切换、任务委派、权限、后台命令、停止、重启、队列及 Bot 多端控制完成受影响路径回归 |

所有文件测试使用隔离临时目录。插件、SDK、文件系统及模型请求组装必须实际执行；模型服务器可使用本地测试端点，报告必须区分真实实现和模拟的外部边界。验证不向模型声明不可用的 qmd 工具，不以替身检索冒充能力。

这是运行时与记忆的广泛重构，实施完成时运行完整测试及构建，并在 Vite 开发 renderer 和构建 renderer 中验证受影响的生命周期和页面。Bot 验证覆盖实际 Linux 部署环境；手机与桌面控制同一 Bot 的场景纳入验收。记录提交、工作树摘要、系统、Node／SDK／插件版本、命令、证据和剩余缺口。
