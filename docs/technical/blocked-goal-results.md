# 受阻目标的正常收口

完成检查返回 `blocked` 表示目标尚未完成、存在已说明的阻塞条件。它是正常的任务结果，不是运行异常，也不代表成功。此逻辑适用于所有任务，不识别命令名称、供应商、网址或特定错误文字。

`goal-driver.mjs` 保存校验事实、阻塞原因、已有证据、剩余事项和下一步，返回结构化 `blocked` 结果。共享 `goalRunOutcome` 将其映射为 `blocked`，拒绝缺少原因或同时声明完成／等待答复／预算触顶的冲突结果。取消优先于正常结果。

PC 与 Bot 将该结果正常闭合到对话流：释放执行槽、保留 `run.blocked`，使用普通说明展示原因和后续条件。工具自己的真实错误状态保持不变。运行账本将 `blocked` 作为终态，拒绝旧目标继续发请求或派单；重启保留受阻状态，不自动重放，用户可以提交新的明确请求。新受阻结果仍产生未读和“任务受阻”通知。

`awaiting_user` 保留原来的问题及答复续接语义。模型请求失败、完成校验格式错误、未确认执行、预算／无进展保护以及清理失败继续走原有异常路径。本次没有改动这些异常的处理，也没有针对历史会话或某种工具报错删除、改写错误记录。

实现参考 ZCode 将工具结果交回模型并以检查结果控制继续执行的分层，以及 DSH 将 blocked 作为持久化目标状态的做法；没有复制其代码或引入依赖。主 agent 接收工具结果、决定下一步与最终目标收口是不同阶段，本次仅修正后者的状态传递和展示。
