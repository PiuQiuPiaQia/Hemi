# Bot 目标续跑与完成判断

Bot 的一次用户输入对应一个持续目标。Pi 停止生成只结束一段执行；宿主在后台命令和子任务收口、会话保存后，独立判断整个用户请求是否完成。实现参考本地 ZCode 的目标校验/续跑循环与 DSH 的持久化 Goal 驱动思路，未复制其源码。

`goal-driver.mjs` 保存原目标、轮次、每段请求偏移、完成检查和剩余工作，续跑使用隐藏的 `hemi_goal_continuation` 消息。用户 inputId、rootRunId、generation、冻结模型策略、权限和已有工具事实不变，不创建第二个用户气泡，不重新派发已受理的输入。

默认每段最多 60 次执行请求，主 agent、子 agent、重试、压缩和辅助请求共享；目标累计最多 600 次执行请求、12 段。每段另允许一次不带工具、不重试的完成校验，并单独记录实际 HTTP 请求和用量。单段触顶先等待已受理的工作收口。子任务报告先按 eventId 去重写入 Pi 会话、保存后再确认消费；不在触顶时发起新的模型请求来消费报告。已受理的后台命令在该边界继续等待真实终态，结果只入上下文，不因软额度触顶被取消。随后，若检查仍有可执行的剩余工作，原子保存新轮次后续跑，累计请求数不清零。连续三轮校验的剩余项和证据相同则以无进展收口。达到总预算、校验失败、真实阻塞均记录未完成原因，界面走失败通知，不能记为 completed。

检查输入由当前实际会话的有限文本投影、工具观察和子任务报告组成，不绕过上下文引用权限读取原始快照。校验器不得调用工具，必须返回结构化判定：complete / continue / blocked，及依据、证据、剩余项、下一步。完成必须有证据且无剩余项；格式错误、截断或请求失败均不能放行。校验沿用最后实际执行的已冻结候选，凭据仍按原身份刷新。

运行账本在校验前拒绝仍未收口的请求、工具、进程、派单和后台报告；即使宿主误传 completed，尚未通过校验的目标也只能落为 partial。取消、回卷、销毁会中断校验；迟到校验不能复活目标。重启保留目标与检查记录，但将未收口目标标记 interrupted，等待用户核对，不自动重放未知副作用。既有历史终态不在本次功能更新中改写。

当前自动目标驱动只在 Bot 启用，桌面普通聊天与工作流沿用各自调度；运行账本的诚实终态保护共用。完成检查属于模型判断，不能代替具体任务的测试与验收；日志和子报告不足时应继续补证或明确未确认，不能宣称提供了形式化正确性保证。

## 验证

开发基线为 `67fb7a70849a4bb11cebf59a709118b57c1932cb` 加工作区改动；环境 macOS 26.5.1 arm64、Node 22.22.3。保留了本轮开始时已有的命令生命周期和移动端改动。测试、构建均使用独立临时 HEMI_USER_DATA_DIR，不读取个人会话或模型凭据。

- `npm test`：1900 项，1888 通过、0 失败、12 Windows 专属跳过。
- `npm run build`：TypeScript 和 renderer 构建通过，保留既有 chunk 大小警告。
- `node scripts/check-spacing.mjs`、`git diff --check` 通过。
- 新增真实 Host / Pi SDK / OS 文件写入检查，覆盖同一输入自动续跑、单段触顶恢复、无进展、总轮数预算、无效校验、真实阻塞、校验期间取消，以及后台子报告在共享额度触顶后恰好消费一次、已受理后台命令在触顶后仍正常完成。账本测试覆盖主/子/辅助共享累计额度、每段校验只发一次、未确认执行阻止完成和重启不重放。

验证日志和组件部署证据保存在忽略目录 `.visual/workflow/bot-goal-update/`。最终 Windows 实机和生产接入结果以该目录的部署报告为准。
