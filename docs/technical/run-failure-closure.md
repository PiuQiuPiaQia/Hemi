# 运行异常与终态保存

运行结束与状态保存使用不同的边界。模型、工具和进程的结束以实际执行结果为准；写盘失败不能让已经结束的运行继续占用界面运行槽，也不能授权重发模型请求或工具动作。

桌面普通回合统一经过 `closeConversationRun` 收尾。终态保存最多等待 5 秒；失败或超时会显示保存错误、暂停自动发送，并关闭当前运行的忙碌状态。原有输出保留。已经成功生成、但终态未能确认保存的回合标为 `partial`。保存错误也会返回结果等待方。迟到的保存回调受运行 ID 与 generation 校验，不能关闭或暂停后来的运行。

保存失败时，正在等待抢话或回卷交接的替换输入会保留为待核对输入；被提升的队列项撤销自动派发资格。队列暂停先于运行槽释放，防止关闭后的调度回调直接执行这些输入。

共享运行事实库在 `finishRoot` 写入失败时保留已经确认的结束状态，继续阻止该根目标发出新请求或工具。新任务受理仍要求写入成功，失败受理不会进入可执行内存状态。运行事实库和桌面会话快照分别退避补存，间隔从 1 秒增加到最多 60 秒；补存只写状态，不调用模型、重发命令或恢复队列。失败的临时文件会被清理，旧的已提交文件保持有效。退出和删除会话时会尝试排空待写状态，并释放重试定时器。

浏览器资源回收与运行时占用释放放在终态保存的 `finally` 路径中；等待用户答复的目标继续保留页面。工具或进程清理未确认时，仍沿用现有 `cleanup-unconfirmed` 处理，不把清理失败视为停止成功。

若存储一直不可用并且进程退出，内存中尚未保存的记录无法保证保留。重启从最后一次原子提交恢复，对旧的在途状态标记中断或待核对，不自动重放任务。

验证入口：`node scripts/verify-storage-failure-closure.mjs`。脚本使用新的 `HEMI_USER_DATA_DIR`，分别验证 Vite 与构建 renderer，通过真实文件系统替换目标制造原子写入失败，覆盖失败收尾、保留输出、队列暂停、补存、重载、进程重启，以及恢复后显式执行新任务。它不访问已安装应用的数据或生产服务。
