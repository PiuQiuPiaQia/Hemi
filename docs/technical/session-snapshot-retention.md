# Pi 原生会话持久化与旧档迁移

生产主会话、角色子会话和工作流使用已安装的 `@earendil-works/pi-coding-agent` 1.3.0 原生持久化。正常运行由 `SessionManager.create/open` 维护 JSONL，新增条目直接追加，不再导出整份上下文制作版本快照。瞬时模型验证以及无恢复需求的独立 SDK 测试可以继续使用内存模式。

## 数据分工

| 数据 | 位置与责任 |
| --- | --- |
| Pi 条目树、消息、工具结果、压缩及扩展状态 | `runtime-v2/sessions/pi/*.jsonl`，由 Pi 维护 |
| 会话归属、回卷代次、角色/模型/工作区兼容信息、受控上下文引用、原生文件身份 | `runtime-v2/sessions/metadata/<ref>.json`，Hemi 维护；不包含 header/entries/payload 或 API Key |
| 聊天展示、标题、时间、用量、工作流 | 原有聊天档案；`agentSession` 仅保存 `{storage:'pi',version:1,ref}` |
| 旧快照与旧索引 | 原位置只读保留，作为迁移回退来源；不再生成新的 `entries-*.json` |
| 旧聊天档案的内嵌 SDK 条目 | 首次恢复时导入；在 `sessions/legacy-archives/` 保存一份确定性备份，再切换为原生引用 |

`session-store.mjs` 是兼容入口；实际实现位于 `native-session-store.mjs`。`session-reference.mjs` 为公开档案提供不依赖 SDK 的小型引用协议。

## 迁移与恢复保证

1. 启动时逐个导入旧索引当前指向的完整快照，先校验旧内容哈希、归属和条目链。旧索引、旧快照不改写。
2. 旧条目由 SDK 在内存中规范化，仅在一次性迁移阶段转换为 JSONL。文件先写入私有暂存目录，再经真实 SDK 重新打开、完整比对，成功后原子激活原生文件和业务元数据。
3. 导入目标名由逻辑引用和源内容摘要确定；激活中断后可重试，不重复复制，也不覆盖已追加的新条目。共享同一旧不可变快照的不同逻辑会话会获得相互隔离的可写文件。
4. 公开档案内嵌的旧条目按需导入；同一回卷代次中，落后的公开档案不能覆盖更完整的原生上下文。公开聊天时间线保留，原来的更新时间规则不变。
5. 恢复使用明确的逻辑引用、文件与 SDK 会话身份，不使用“最近会话”猜测归属。保留子会话已有的 generation、roleRevision、工作区和模型兼容校验，旧代次或已替换实例的检查点不能写回。
6. 原生文件缺失、为空、身份不符或含损坏 JSON 行时停止恢复，保留原件，不自动新建空会话。完整末条 JSON 仅缺换行时补回分隔符，防止后续追加粘连。中断迁移的私有暂存目录会在下次启动重试前回收。

新目录使用 0700，业务文件、导入文件及已提交原生文件使用 0600。同一数据目录仍由生产宿主的单实例/单写者规则保护；同进程存储操作使用共享队列。

## 编辑与回卷

公开档案仅记录 `rewindBeforeInputId`。恢复时通过 SDK 查找 `hemi.input` 锚点并使用 `branch/resetLeaf` 回卷，再追加不进入模型上下文的 `hemi.rewind` 自定义条目，使选定分支能跨重启保留。找不到锚点时从保留的展示历史重建，不能沿用包含旧目标的压缩摘要。旧分支可以保留在 Pi 的历史树中，但不进入当前模型上下文。

## 验证

- 基线：`f388e9039eaf28a1b6655f3fa2b4cba02e4b3974`（v0.2.9）加本次工作区修改。
- 环境：macOS 26.5.1、Node.js v22.22.3、Pi SDK 1.3.0、Electron 44.0.0。
- `session-store.test.mjs` 使用真实 SDK 和临时文件，覆盖旧快照/内嵌档迁移、只追加不复制、跨进程读取、迁移重试、共享旧版本隔离、回卷、损坏与归属保护、尾部换行恢复。
- `native-session-restart.test.mjs` 使用三个独立 Node 进程、真实 Bot/core/Pi 和本地 SSE 模型：先产生聊天及一次工具执行，构造旧版公开档与私有快照，第二个进程迁移并续聊，第三个进程再次原生恢复；检查真实模型请求包含旧上下文、原时间线完整、工具未重跑。
- `verify-session-audit.mjs` 的 `context` 场景通过桌面生产 IPC 和真实 Pi 检查停止、释放驻留实例、从原生存档继续对话以及不再生成整会话副本。其旧 `retry` 场景仍假设主备 503 后立即终止，与现有 30 分钟模型恢复策略不符，不能用该场景的旧超时判断持久化故障。
- 测试全部使用隔离数据和合成凭据，没有迁移用户个人存档；正式安装版须更新到包含此修改的新构建后，在首次启动/打开旧会话时执行迁移。

2026-10-25 最终实测：`npm test`（含 SDK 预构建）共 1,766 项全部通过；`HEMI_AUDIT_CASES=context` 的桌面 Electron 生产 IPC 验收 11 项全部通过。桌面结果记录位于 `.visual/workflow/vision/session-audit-controlled-1792891476849/result.json`。未执行正式版打包安装或 Windows 应用回归。

2026-10-25 发版前真实存档副本预演：23 个旧快照引用完成导入，3,998 个 SDK 条目经真实 SDK 规范化后逐项摘要比对一致；原始备份与个人数据未进入仓库。
