本次基准为 `main` 的 `1e1697b84fc2099a1b1165d163c5f4cd5bcbf6c9` 加工作区改动。同工作区还有其他任务的改动，未回退或提交这些改动。环境：macOS arm64、Node 22.22.3、Electron 44、Xcode iPhoneOS 26.5。未发布新的桌面版本。生产目标的真实状态单独记录，隔离测试通过不代表生产已经安装。

## 执行与同步契约

- PC 本地、PC Bot、iOS 均通过 `createConversation` 管理命令日志、冻结的输入／运行目标、队列操作、回执核对与恢复。PC 通过同一个 `createBridgeConversationTransport`；iOS 的原生 RPC/WSS 只实现端口。执行和队列派发仍由唯一的 Host 控制器裁决，客户端不另建派发器。
- PC 本地发送和队列入口已接到 SDK。原生语音、TTS、模型与工作区冻结由本机宿主执行。新的本地 IPC 回执日志独立于大历史文件，支持按原请求身份查询；重复身份不能改变载荷，未确认结果不会自动重放。
- SDK 先订阅，再由订阅端提供一次基线与 ready。正常增量、ready、命令完成不再各自拉整份快照。版本缺口才补取；未知操作的回执查询不排在历史读取后面。元数据读取使用 revision/bootId 和 metadata 投影，命令回执直接更新控制权／设置，再后台刷新。
- 实时通道负责连接状态，replica 负责数据是否同步。慢读、旧请求失败和可重建缓存故障不能把健康实时通道标成离线。手动／前后台恢复由共享连接所有者合并；原生 AbortSignal 会实际取消对应 NWConnection。
- 持久化的 waiting 输入重启后需要用户确认，sending 恢复成 unknown 后仅查询。不会因更新或恢复连接而静默执行旧输入；停止目标、编辑版本、排序列表和控制权 epoch 在点击时冻结。

## 最近窗口与往上翻历史

协商 `windowed: true` 的远程客户端只同步最近最多 32 个时间线项，目标预算 256 KiB。单个超大项仍保留以保证实时内容完整，因此预算对该项是软上限。运行、队列、权限与当前控制元数据不依赖历史分页。旧客户端的完整快照与游标协议仍兼容。

旧记录完整保存在 Host，通过只读 `flow.history` 按 generation 与 before 索引分页。向上滚到顶部会自动读取一页，同时保留可点击的“加载更早消息”。加载不占用命令通道；新命令或版本切换会取消过期历史读取。SDK 将页面作为只读展示前缀合并，并接收已加载历史项的更新。回卷或新进程纪元会丢弃过期前缀。虚拟列表使用统一的 prepend 锚定，自动追随最新输出则另由用户滚动意图控制。

客户端离线检查点只保存最近窗口。已主动翻开的历史可以留在当前视图中；不会在每个增量上克隆并序列化整份历史。

## 配额错误

真机在更新前的 WebView Local Storage 约 5.11 MB，其中旧快照约 3.84 MB、目录约 1.09 MB。用户在 iOS 看到 `The quota has been exceeded`。这不是据此推断模型账户余额的证据；本机真实数据与浏览器复现支持 Local Storage 配额路径。

快照改用 IndexedDB，并最多约每秒保存一次最新引用。迁移扫描同一 WebView 下各 Bot 的旧快照键，先提交有界检查点，再删除对应旧缓存；已有较新检查点优先。迁移或事务失败时保留旧副本。草稿、waiting/unknown 操作和配对身份不参与回收。

目录缓存去掉可再次从 Host 查询的 usage 明细；目录缓存保存失败不会拒绝已确认的操作或断开实时连接。草稿与操作日志保存失败仍明确阻止发送，并显示存储空间提示。
